- `<topic>-packet.pdf`: the student packet, ending with its Check-In page
- `<topic>-answer-key.pdf`: the same pages filled in (the Check-In too), with a short teacher note on the learning page

## Check-Ins and assessments

**Check-Ins.** The last page of every packet (and answer key) is its Check-In. The same page is also saved on its own as `<slug>-check-in.pdf` (and `-check-in-key.pdf`) in both inks, for a retake. It has one or two problems of each kind from that packet, with no help. The key shows the mastery line: 80% of the problems correct.

**Grade-level assessments** are in `assessments/`, in color and black-and-white:

Each answer key ends with a **scoring sheet**: every part, the packet it checks, and a score line. Use the **pre-assessment** for placement: start a student at the first packet where they miss more than 1 problem in its parts. Use the **post-assessment** to see growth: a part with more than 1 miss means that packet needs review.

Check-in and assessment problems are chosen automatically. Problems that no practice packet used come first, and none is repeated across all the check-ins and assessments. The only exception is the ten buddies, where there are only 11 facts.

## curriculum.json (for the website)

Every build also writes `curriculum.json`: the packets in teaching order and every Check-In and assessment question as printed (number, part, the packet it checks, a short prompt and the answer). The website reads it so tutors can mark tests question by question and get a recommended next packet. Copy it over with the PDFs (`npm run sync:curriculum` in the website repo). It only depends on the problems, not the fonts, and the build stops if an answer it works out ever disagrees with the answer key.

## Rebuilding

```bash
python build_worksheets.py
```

**Previews off a Mac.** `WEMATH_PREVIEW_FONTS=<folder> WEMATH_OUT=<folder> python build_worksheets.py` builds with stand-in fonts (Inter and Liberation Sans, as `.ttf`) into another folder, to check layouts in the cloud. Never commit PDFs built that way.

Needs the packages in `requirements.txt` (`python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`) and the macOS system fonts (Avenir Next, Arial Rounded). The fonts can't be committed, so the PDFs are built on a Mac; elsewhere you can edit the generator but not rebuild. The build stops with an error if any question appears twice across all the packets.
